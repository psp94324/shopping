# 4단계: PRD 준수 여부 및 버그 검토 (Playwright 활용)

## 프롬프트

```
PRD.md와 app.py를 기준으로, 앱이 PRD대로 개발되었는지와 버그가 있는지 자세히 검토해줘.
코드 리뷰와 Playwright를 이용한 실제 브라우저 테스트를 모두 해줘.
문제를 찾으면 바로 고치지 말고, 먼저 보고서로 정리해서 보여줘.

[준비]
1. 기존 shopping_list.json이 있으면 shopping_list.backup.json으로 백업한 뒤 삭제해서 빈 상태로 시작
2. `streamlit run app.py --server.headless true --server.port 8501`을 백그라운드로 실행
3. Playwright로 http://localhost:8501 접속 (Streamlit은 렌더링이 비동기이므로 각 동작 후 요소가 나타날 때까지 대기)

[A. 코드 리뷰]
- PRD 4장 F1~F5 각 요구사항이 코드에 구현되어 있는지 항목별로 대조
- PRD 5장 데이터 모델 필드/타입 일치 여부
- 위젯 key 중복 가능성, 콜백/rerun 타이밍 문제, 리스트 순회 중 수정
- JSON 파일 손상/누락 시 예외 처리
- 동시 접속 시 공유 파일 덮어쓰기 문제 (PRD 7.3 한계와 관련)

[B. Playwright 기능 테스트 — PRD 10장 인수 조건]
각 시나리오마다 스크린샷을 screenshots/ 폴더에 저장해줘.
1. 빈 상태: 안내 문구 표시 확인
2. 추가: "우유" 수량 2 추가 → 리스트에 표시, 입력 필드 초기화 확인
3. Enter 키로 추가: "계란" 입력 후 Enter
4. 빈 이름 / 공백만 입력 후 추가 → 경고 표시, 추가되지 않음
5. 수정: "우유" → "저지방 우유", 수량 3으로 저장 → 반영 확인
6. 수정 취소: 값 변경 후 취소 → 원래 값 유지
7. 빈 이름으로 수정 저장 → 저장 거부
8. 체크: 항목 체크 → 취소선 표시, 아래로 이동, "N / M 구매 완료" 갱신
9. 체크 해제 → 원래 상태로 복귀
10. 개별 삭제: 해당 항목만 삭제되는지
11. 체크된 항목 모두 삭제 → 체크된 것만 삭제
12. 새로고침 후 데이터 유지
13. 버튼 1회 클릭으로 즉시 반영되는지 (두 번 눌러야 하는 버그 확인)

[C. 엣지 케이스 테스트]
- 50자 이름, 50자 초과 입력 시도
- 이모지/특수문자/HTML 태그(<b>test</b>) 이름 → 깨지거나 HTML이 실행되지 않는지
- 같은 이름 아이템 여러 개 → 수정/삭제가 올바른 항목에만 적용되는지
- 아이템 30개 이상 추가 시 성능 (PRD 9장: 1초 이내 반영)
- 편집 중에 다른 아이템 체크/삭제
- 수량 0, 음수, 소수 입력 시도
- shopping_list.json을 깨진 JSON으로 바꾼 뒤 새로고침 → 앱이 죽지 않는지

[D. UI / 반응형 테스트]
- 뷰포트 1280x800, 390x844(모바일)에서 스크린샷 → 레이아웃 깨짐, 버튼 겹침 확인
- 다크 모드(prefers-color-scheme: dark) 에뮬레이션 → 글자 가독성 확인
- 브라우저 콘솔 에러 확인

[정리]
- 테스트 후 Streamlit 프로세스 종료
- 백업한 shopping_list.json 복원

[보고서 형식] — review_report.md로 저장
1. 요약: 전체 통과/실패 개수
2. PRD 준수 표: 요구사항 ID | 구현 여부(✅/⚠️/❌) | 근거
3. 테스트 결과 표: 시나리오 | 결과 | 스크린샷 경로
4. 발견된 문제 목록 (심각도 높음/중간/낮음 순)
   - 문제 설명 / 재현 방법 / 원인 코드 위치(app.py:줄번호) / 수정 제안
5. 개선 제안 (PRD 범위 밖이지만 권장하는 사항)

보고서를 보여준 뒤, 내가 승인하면 그때 수정하고 같은 테스트를 다시 돌려서 확인해줘.
```
