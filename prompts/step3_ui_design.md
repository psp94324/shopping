# 3단계: UI 디자인

## 프롬프트

```
PRD.md 6장(화면 구성)과 9장(비기능 요구사항)을 참고해서 app.py의 UI를 다듬어줘.
기능 로직(load/save/add/update/delete/toggle)은 바꾸지 말고 화면 표현만 개선해줘.

[레이아웃]
- 위에서부터: 제목 → 진행 현황 → 입력 폼 → 아이템 리스트 → 일괄 삭제 버튼
- 입력 폼: st.columns로 [이름 입력 | 수량 | 추가 버튼]을 한 줄에 배치 (비율 예: 6:2:2)
- 아이템 한 줄: st.columns로 [체크박스+이름 | 수량 | 수정 | 삭제] 배치
- 섹션 사이는 st.divider()로 구분
- "구매할 항목" / "구매 완료" 소제목으로 미체크/체크 영역 구분 (해당 항목이 있을 때만)

[스타일]
- st.markdown(unsafe_allow_html=True)로 최소한의 CSS 주입
  - 체크된 항목: 취소선 + 회색(opacity 0.5 정도)
  - 버튼 높이/간격 정리, 아이템 행 사이 여백 통일
- 버튼에 아이콘 사용: ✏️ 수정, 🗑️ 삭제, ➕ 추가, 💾 저장, ✖️ 취소
- 진행 현황: "🛍️ 3 / 7 구매 완료" + progress bar, 모두 완료 시 "🎉 모두 구매했어요!" 표시
- 빈 리스트 안내 문구를 친근하게 (예: "아직 아이템이 없어요. 위에서 추가해보세요!")
- 추가/삭제 시 st.toast로 짧은 피드백

[테마]
- .streamlit/config.toml 생성: primaryColor 등 기본 테마 색상 지정
- 라이트/다크 모드 모두에서 글자가 잘 보이는지 고려 (CSS에 고정 배경색 쓰지 말 것)

[모바일 대응]
- 폭 400px 정도의 좁은 화면에서도 버튼이 겹치거나 잘리지 않게
- 긴 아이템 이름(50자)이 레이아웃을 깨뜨리지 않게 (줄바꿈 처리)
- 버튼은 손가락으로 누르기 쉬운 크기

[완료 조건]
- 2단계의 모든 기능이 그대로 동작한다.
- 데스크톱과 모바일 폭에서 모두 레이아웃이 깨지지 않는다.
```

## 확인 체크리스트
- [ ] 2단계 기능이 모두 그대로 동작한다.
- [ ] 체크된 항목이 회색과 취소선으로 구분된다.
- [ ] 좁은 화면(모바일)에서도 레이아웃이 유지된다.
- [ ] 다크 모드에서도 글자가 잘 보인다.
